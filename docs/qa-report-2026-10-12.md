## Android 0.1.2 follow-up

Fixed Capacitor numeric arguments: getLong ignored JSON Integer account IDs,
which made playbackSettings reject valid sessions and report cloud sync as offline.
BridgeNumbers regression tests cover Integer/Long/Double IDs, timer values and
invalid/unsafe identities. Audio resolution now waits up to 90s, matching the
server proxy; previously clients abandoned successful resolves at 45s, as seen
in backend BrokenPipe logs. The control state now follows playWhenReady while
buffering, shows a spinner, and retries on a manual Play after errors.

Signed release compilation, unit tests and lint passed. HTTP /v1/status and
/health were operational with certificate verification enabled. No phone is
attached to adb, so actual music on the owner's Honor is still unverified.
The owner clarified that chat sending was not tested; no chat messages were
sent and no chat defect is claimed as fixed.

## Android 0.1.3 device follow-up

ADB reproduced the playback crash on the owner's Honor RMO-NX1: AudioProbe.queueInput attempted ByteBuffer.put on the shared empty buffer itself. Empty pipeline inputs now return immediately; two JVM regressions cover empty draining and preservation of PCM across buffer reuse.

The signed update was installed over 0.1.2 without removing app data. The owner confirmed sound and swipe navigation in both players. The Android release build, lint, 14 JVM cases and shared TypeScript checks passed. iOS source has not been built or device-tested here. Nothing was pushed or deployed by the agent.

Final prepared APK: 0.1.3/build 1003, 12,110,849 bytes, SHA-256 c772ed9630497af385fe17d45c90facb66978e489f2405c5fcbed0de5a85f702.
